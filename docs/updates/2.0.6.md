# Well Importer 2.0.6

## Назначение обновления

Версия 2.0.6 закрепляет текущую стабильную кодовую базу Well Importer перед дальнейшим развитием плагина. Этот документ фиксирует основные функциональные изменения, критические исправления и результаты сверки исходников, попавших в репозиторий.

## Крупные изменения

### Единое поле номера скважины

- Для точек бурения и площадных кругов используется единое логическое поле `Номер скважины`.
- Устаревшее служебное поле `WI_NUM` больше не используется как отдельное рабочее поле нового импорта.
- Сохранена фоновая совместимость со старыми слоями, где `WI_NUM` ещё может присутствовать.
- При импорте номер площадного круга берётся из подготовленной записи соответствующей пробуренной скважины.
- Поиск поля учитывает как физическое имя поля QGIS, так и его псевдоним.

### Критическое исправление импорта номера в площадной круг

Исправлена ошибка, при которой созданный площадной круг мог оставаться без номера скважины. Теперь номер записывается непосредственно в поле `Номер скважины`; при невозможности корректной записи импорт не должен оставлять несогласованную пару точка/круг.

### Раздельное исправление точек и кругов

В Центре управления операции исправления разделены на две независимые команды:

- `Исправить площадные круги` — создание отсутствующих кругов, исправление площади, центрирование по точке и синхронизация измерительных атрибутов;
- `Исправить точки бурения` — восстановление однозначно определяемого номера, восстановление геометрии по связанному кругу, заполнение пустого года и создание отсутствующей точки по пронумерованному кругу.

Уже заполненные корректные значения не должны перезаписываться без необходимости.

### Профили настроек

- В конец выпадающего списка профилей добавлен пункт `+ Добавить профиль…`.
- Новый профиль создаётся из текущих параметров главного окна.
- При совпадении имени предлагается подтвердить перезапись.
- Кнопка сохранения обновляет текущий выбранный профиль без повторного запроса имени.
- Встроенный профиль `Солевая съёмка 33 га` остаётся защищённым от удаления.

## Состав стабильного snapshot

В каталоге `WellImporter/` находится полный комплект текущего плагина: 37 файлов, включая Python-модули, `metadata.txt`, Qt Designer UI, QRC-ресурсы и иконку.

Основные подсистемы:

- импорт из буфера, XLSX, CSV и TXT;
- DD/DMS/проектные координаты и преобразование в EPSG:4326;
- интеллектуальный контроль дублей;
- создание точек и площадных кругов 33 га;
- контроль качества геометрии и атрибутов;
- история партий и отмена последнего импорта;
- архивирование и выездной GeoPackage/QGIS-проект;
- определение земельных участков и кадастровых номеров;
- поиск и карточка скважины;
- Центр управления;
- профили пользовательских настроек.

## Финальная сверка перед слиянием

Перед Pull Request выполнена сверка ветки `chore/full-source-sync-2.0.6` с `main` и локальным стабильным архивом версии 2.0.6:

- версия в `metadata.txt` остаётся `2.0.6`;
- в дереве плагина присутствуют все 37 файлов стабильного snapshot;
- относительно первоначального `main` добавлены 28 недостающих файлов исходного кода, что вместе с 9 уже присутствовавшими файлами даёт полный комплект из 37 файлов;
- последние изменения профилей присутствуют в `well_importer_dialog.py`;
- раздельные операции исправления точек и кругов присутствуют в Центре управления;
- единое поле `Номер скважины` и логика переноса номера в площадной круг сохранены;
- служебные и временные артефакты (`__pycache__`, `.pyc`, ZIP-сборки, локальные QGIS-проекты) в исходное дерево не включаются согласно `.gitignore`.

## Проверки

Для локального стабильного архива 2.0.6 ранее выполнялись статические проверки Python-модулей, структуры ZIP и обязательных файлов плагина. Полный запуск PyQGIS GUI и провайдеров данных должен дополнительно подтверждаться в установленном QGIS 3.28+ при пользовательском тестировании.

## Правило дальнейшей разработки

После этого слияния `main` считается эталонной стабильной веткой версии 2.0.6. Новые крупные функции разрабатываются в `feature/*`, исправления — в `fix/*`; значимые изменения проходят через Pull Request и сопровождаются обновлением документации/CHANGELOG при необходимости.
